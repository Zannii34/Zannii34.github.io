inspect-http

A single-file CLI tool that inspects HTTP responses: status code, timing, headers and security posture. Runs on any Python 3.8+ with no dependencies.

The problem

When you deploy a site, you want to know three things fast: is HTTPS working, are the security headers set, and how slow is the first byte. curl and httpie print raw headers. Neither gives you a summary. I wanted one command that did.

What it does

  • Follows redirects and reports the final URL
  • Prints status, timing, size, server, content type, encoding
  • Measures time-to-first-byte and total
  • Checks five common security headers
  • Exit code 0 for 2xx, 1 for connection failures

Technical decisions

  • Stdlib only. No requests, no httpx, no click. The whole tool fits in 150 lines and runs anywhere Python 3.8+ is installed, including servers where you cannot pip install anything.
  • argparse over click. The tool takes one URL and one optional timeout. click is overkill.
  • Auto-disable colour when output is not a TTY. Piping to less or a file gives clean text without escape codes.
  • Exit codes. Non-2xx returns 0 (the response was fine). Connection failure returns 1 (the server could not be reached). Scripts can branch on this.

Limitations

  • No DNS / TCP / TLS timing split, because urllib does not expose them
  • No HTTP/2 support (stdlib does not do it)
  • No cookie jar or authentication
  • Single-request only; no load testing

What I learned

Writing a good CLI is mostly about restraint. Every feature you do not add makes the tool faster to run and easier to remember. The tricky part was detecting whether to use colour and resetting it correctly so piped output stays clean.
