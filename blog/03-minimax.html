How minimax actually works (with my Tic-Tac-Toe AI)

Minimax is one of those algorithms every AI course teaches and almost nobody implements. It sounds simple and then you write it and it does something weird.

What minimax does

Consider the game tree. Every node is a board state. Root is the current position. Children are available moves. Leaves are terminal (win, loss, draw).

Scores: +10 for AI win, -10 for AI loss, 0 for draw.

For non-terminal nodes:

  • Maximising player (AI): score = max of children
  • Minimising player (human): score = min of children

That is it.

The code

function minimax(board, isMaximising) {
  const result = checkWinner(board);
  if (result === "O") return 10;
  if (result === "X") return -10;
  if (result === "draw") return 0;

  let best = isMaximising ? -Infinity : Infinity;

  for (let i = 0; i < 9; i++) {
    if (board[i]) continue;
    board[i] = isMaximising ? "O" : "X";
    const score = minimax(board, !isMaximising);
    board[i] = "";
    best = isMaximising
      ? Math.max(best, score)
      : Math.min(best, score);
  }

  return best;
}

The bug I hit

My first version was unbeatable. My second was not. The difference was one line: I swapped isMaximising in the recursive call, so the AI evaluated its own moves as if they were the opponent. It helpfully set up moves that let me win.

Lesson: in recursive algorithms, the argument you pass to the recursive call is where 90% of bugs live. Test with a 3-move game, not a 9-move one.

Performance

Tic-Tac-Toe has at most 9! = 362,880 leaf nodes. Minimax explores all of them in about 50ms in JavaScript. No optimisation needed.

For bigger games, add alpha-beta pruning: skip branches that cannot possibly be better than what you already found.

Why this matters

Minimax is the foundation of game-playing AI. Alpha-beta pruning is minimax plus a bookmark. If you understand minimax, you understand the family. And it takes about 30 lines.
