SECURITY

Why I use crypto.getRandomValues, not Math.random

I built a password generator. The first version used Math.random() because that is what every tutorial uses. Then I read the MDN page.

Note: Math.random() does not provide cryptographically secure random numbers. Do not use them for anything related to security.

What Math.random() actually returns

A double-precision float between 0 and 1. In V8, it is xorshift128+. Fast, deterministic given internal state, not cryptographically secure.

"Not cryptographically secure" means: observe enough outputs, predict future ones. For a password generator, that is catastrophic.

What crypto.getRandomValues() returns

Bytes from the OS CSPRNG: getrandom(2) on Linux, BCryptGenRandom on Windows, SecRandomCopyBytes on macOS. The same sources the OS uses for TLS keys.

The code change

Before:

pw += chars[Math.floor(Math.random() * chars.length)];

After:

const bytes = new Uint32Array(length);
crypto.getRandomValues(bytes);
for (let i = 0; i < length; i++) pw += chars[bytes[i] % chars.length];

Two lines changed. That is the whole fix.

The subtle bug I introduced

Modulo bias. If chars.length does not evenly divide 2^32, some characters are slightly more likely than others. The bias is tiny for 62 characters, but it exists. The proper fix is rejection sampling.

What this taught me

Every obvious choice in code has a default and a correct choice. Math.random() is the default. crypto.getRandomValues() is the correct choice for anything security-adjacent.
