Deploying Flask with Caddy and Waitress (and why I stopped using nginx)

Every Flask tutorial tells you to run flask run in production. Every Flask tutorial is wrong. Here is what I ended up with after deploying to a real VPS.

The stack

  • Caddy - reverse proxy, automatic TLS via ACME
  • Waitress - pure-Python WSGI server
  • Flask - the app

That is it.

Why Caddy over nginx

The single deciding factor: Caddy renews certificates automatically. With nginx, you configure certbot, add a cron job, and six months later discover the job did not run.

Caddy config for a Flask app:

mazetechhub.co.za {
    reverse_proxy localhost:8000
}

That is the whole config. TLS, HTTP to HTTPS redirect, and reverse proxy in three lines.

Why Waitress over gunicorn

I develop on Windows and deploy on Linux. Gunicorn does not run on Windows. Waitress does. Same WSGI server in dev and prod means less "works on my machine."

What broke

SQLite + concurrency = silent failures. My enquiry form returned 200 but the row was not in the database. SQLite was locking during concurrent writes. Fix: enable WAL mode and retry with backoff. Make failures return 500, not 200.

Caddy does not run your app. Caddy reverse-proxies. Something has to actually run Waitress. This is where one config file became two.

What I would do differently

  • Add health-check monitoring from day one
  • Version the Caddyfile in the repo
  • Write the Waitress unit as a template

The point

You do not need Kubernetes to deploy a Flask app. You need three tools and the discipline to notice when things are silently failing.
